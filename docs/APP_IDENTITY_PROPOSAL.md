# App 名称与图标提案

日期：2026-10-25。当前为设计比较稿，尚未选定或接入 App。

## 当前问题与设计目标

现场源码中 Android 桌面名称仍为 `mobile_app`；历史图标候选为深灰底、紫色日历与勾，与现有蓝橙界面的联系较弱。此次以运动队日常训练签到、管理员点名、平板横屏和在线/离线工作为场景，提供三组可独立选择的名称与图标。

目标是名称易读易记、桌面小图标容易识别、与现有界面连续。图标不使用文字、复杂人物或项目并未提供的 GPS / 人脸识别符号。设计说明中的优劣是设计判断，并非用户偏好或实际识别率测试结论。未做外部重名、商标或应用市场检索，不宣称名称独占或可注册。

## 三套方向

| 方案 | 名称与推荐用法 | 图形与含义 | 优点 | 取舍 |
|---|---|---|---|---|
| A，优先推荐 | 桌面「队齐」；首次说明「队齐 · 运动队签到」 | 三枚队员圆点 + 白色确认笔画，主蓝底、橙色中心点 | 两字短名称，团队属性明确，与新版蓝橙配色连续 | 初次接触需副标题解释用途；口头同音「对齐」需结合场景理解 |
| B | 桌面「到场」；首次说明「到场 · 签到考勤」 | 开口圆环 + 橙色勾，深蓝底 | 简洁、通用，容易延展到更多集合场景 | 名称语义通用，运动队特征较弱 |
| C | 桌面「训练签到」 | 简化点名册 + 橙色勾 | 用途清楚，交接和找 App 时容易理解 | 描述性名称，品牌辨识较弱；24 px 下图标细节更多 |

建议先选 A「队齐」，因为本项目的日常使用主体是运动队，名称和图形都能表达团队确认这一核心动作。橙点只作为品牌元素，不表示某位队员已签或整队全部到齐；图标也不随真实签到状态变化。

名称与图标可以交叉选择，例如「到场」搭配 A 图形；确认后再统一图形含义与文字说明。

## 统一视觉和品牌使用

- 主色沿用 `mobile_app/lib/theme/app_theme.dart`：蓝 `#1E40AF`、橙 `#F97316`、白 `#FFFFFF`。B 的深蓝 `#172D69` 为图标备选背景，不要求改全局界面。
- 桌面名称尽量简短；登录或关于区域展示完整品牌与功能说明。具体功能页继续使用「今日签到」「成员管理」「数据看板」等明确标题，避免每页堆叠品牌。
- App 打开不增加强制片头或等待动效。若后续加入品牌过渡，复用现有短过渡和减少动态效果策略，页面就绪即可操作。
- 颜色不能独立承载图标含义；灰度预览仅检查轮廓，不等同 Android themed icon 成品。

## 选定后的接入清单

1. 确定一个名称和一个图形，收敛间距、笔画和小尺寸细节；需要公开分发时再按确定名称检查外部重名。
2. 导出 Android 各密度传统图标、前景/背景分离的 adaptive icon，以及 Android 13+ 单色资源。按目标平台当前官方要求核验安全区和裁切；当前 SVG 是概念母版，不冒充最终 adaptive XML。
3. 统一 Android label、Flutter 应用标题及现有登录/关于品牌入口；不改 `applicationId`、签名和数据目录。其他平台在确认其构建/使用范围后处理。
4. 检查资源与名称引用，运行 Flutter 项目检查及构建；在独立 AttendanceLab 保数据安装核对桌面/设置名称、各形状裁切与升级兼容。真机由用户手动验收。

本轮只增加设计文件，不修改移动端业务、Web、数据库、签名、设备或安装包。此前 111 项 Flutter 测试结果属于前一实现阶段，不能作为品牌接入已验收的证据。

## 本轮验证口径

检查三份 SVG 结构、方案页离线资源加载、四项预览控件状态、桌面与窄屏排版、32/24 px 轮廓及圆形裁切，并用无界面浏览器渲染后目检。具体结果记录在唯一活动状态 `work/ACTIVE_TASK.md`；设计稿完成不代表名称已选定或 App 已改名。
