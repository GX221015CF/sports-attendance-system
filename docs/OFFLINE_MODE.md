# 显式离线签到模式

## 使用流程

用于管理员持有一部公共 Android 手机、成员依次签到的场景。不要求升级 Supabase 付费计划。离线让现场不能连接服务时仍可记录，不改变校园网对服务的可达性。

1. 在流量或能访问服务的网络下，点击首页「离线模式」。
2. 点击「联网准备名单」，登录管理员帐号，确认读取并保存成员、分组。此按钮只准备名单，不上传任务。
3. 无网络时「创建离线签到」：填写标题、规定时间、结束时间，选择缓存成员，发布到本机。
4. 成员进入任务依次签到；可填写或清空备注，查看人数、各状态数量和出勤率。
5. 点击「结束本机任务」，或在截止后打开/刷新任务时由本机结束；未签到成员记为缺勤。
6. 换到能访问服务的网络，返回列表，逐个点击「手动同步」并确认。需使用准备该任务名单时的帐号。
7. 整单确认成功后，在 Web 历史任务中查看、导出；本机保留只读结果。

模式记住上次选择。恢复网络、重启、刷新、切回在线，都不会上传本机任务。在线模式沿用现有实时功能，与本机离线任务分开。

## 范围与签到规则

- 离线只创建新任务，不下载、续签或修改已有云端任务。
- 成员、分组离线只读；需更新时明确点击「联网准备名单」。更新名单不改变已发布任务的本机成员快照。
- 进行中的任务不能同步；本版没有 Web 纠错、冲突审核或自动补传。
- 可保存多个本机任务。结束后不能再签到；首次同步前仍可改备注。
- 首次真正发起上传前锁定最终快照。失败后只重试同一份结果，不能再改本机备注，避免服务器已收到但手机没收到确认时内容不一致。

状态保持 `pending`（未签到）、`normal`（确认时刻不晚于规定时间）、`late`（超过规定但不超过结束）、`absent`（任务结束时仍未签到）。迟到分钟数向下取整，不足一分钟记一分钟。结束时间的精确时刻仍可签到，超过才禁止；弹窗是预览，保存时重新检查确认时刻。备注不能改变签到结果或时间。

离线使用手机系统时钟，上传保留原始时间和最终结果，不按上传时刻重算。请事先校准时间，过程中不要手动改时钟。服务器拒绝明显未来的结束时刻、矛盾的状态/时间或成员缺失等异常。本版不能证明手机时间没有被人为修改。

## 保存和失败处理

本地数据位于应用私有 SQLite 数据库 `sports_attendance_offline_v1.db`。发布、签到、结束、快照锁定均使用事务；不同服务配置的数据隔离，名单与任务保存所属帐号。缓存必要的姓名、学号、分组等，不缓存电话、密码或服务密钥。

手动同步通过 `public.sync_offline_attendance(jsonb)` 一次事务写入已结束任务、全部结果和私有回执。稳定 UUID 和内容校验使重试不重复创建；只插入新任务，不覆盖已有云端任务。

失败或超时保留本机数据。超时不代表服务器没收到，应换有效网络手动重试，由回执确认。原成员被云端删除、任务 ID 冲突、已同步的云端任务后来被删除时会拒绝，不擅自补建成员或恢复被删任务。请保留记录排查，不要卸载、清除数据或反复改配置。

本版无备份导出、本机任务清理、跨手机搬迁或数据库加密；未同步结果只有本机一份。手机丢失、卸载或清除数据会丢失记录。公共手机由管理员保管，不填涉密备注。本版不是防篡改考勤凭证，也没有新增独立管理员锁。

## 数据库与安全

- 核心表、旧策略不变；依赖已存在的 `session_members.remark` 列。
- 迁移：`supabase/migrations/20261009185846_offline_attendance_sync.sql`。
- `offline_private.sync_receipts` 开启 RLS，按帐号隔离；回执不因云端任务删除而删除，阻止误恢复任务。
- RPC 使用调用者权限（`SECURITY INVOKER`）、空 `search_path`，只有 `authenticated` 可调用。不使用服务端密钥，不绕过旧表权限。
- 登录不等于完整管理员角色授权。旧宽松开发策略仍是遗留风险，本任务未修复或宣称修复整个生产权限模型。

本迁移已于 2026-10-10 在当前项目增量部署。换服务项目时，应先部署基线表、备注列、本迁移，再通过其本地配置构建。真实配置不可写入文档或 Git。

部署前后安全顾问均仅报告原有泄露密码保护未开启，本任务未修改认证设置或购买计划。参见 [Supabase 密码保护说明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。这不替代上述旧权限风险的人工审查。
