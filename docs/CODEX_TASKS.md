# Codex 开发任务清单

本文档用于指导后续使用 Codex 分步骤开发运动队签到考勤系统。开发时应保持任务小、边做边验证，避免一次性生成整个项目。

## 一、项目开发原则

- 每次只做一个小任务。
- 修改前先说明计划。
- 完成后总结修改文件。
- 运行必要检查。
- 不一次性生成整个项目。
- 不引入无关复杂功能。
- 不修改未要求修改的文件。

## 二、开发阶段总览

1. Supabase 数据库配置
2. Figma UI 设计
3. 管理员后台项目初始化
4. 管理员后台基础布局
5. 成员管理
6. Excel 导入成员
7. 签到任务创建
8. 签到详情和导出
9. Flutter App 项目初始化
10. Flutter App 基础 UI
11. Flutter App 接入 Supabase
12. 签到逻辑
13. 缺勤逻辑
14. 安卓真机测试
15. 打包 APK

## 三、每个阶段的 Codex 提示词模板

### 1. Supabase 数据库配置

```text
请帮我配置 Supabase 数据库。当前项目已有 database/schema.sql。请先检查 SQL 文件内容，不要修改代码。然后指导我在 Supabase 控制台创建项目、执行 schema.sql，并验证四张表和索引是否创建成功。每一步完成后停下来让我确认。
```

### 2. Figma UI 设计

```text
请根据 docs/PRD.md 为运动队签到考勤系统整理 Figma UI 设计需求。不要写代码。请输出页面清单、组件清单、颜色规范、字体建议和管理员后台/安卓 App 的核心界面结构。每一步完成后停下来让我确认。
```

### 3. 管理员后台项目初始化

```text
请在正式项目中初始化管理员后台项目。技术栈为 React + Vite + TypeScript + Ant Design。请先说明目录规划和创建命令，等我确认后再执行。不要实现业务页面，只完成项目初始化和依赖安装。
```

### 4. 管理员后台基础布局

```text
请为管理员后台创建基础布局，包括侧边栏、顶部栏、路由结构和空页面占位。不要实现业务逻辑。完成后运行必要检查，并总结修改文件。
```

### 5. 成员管理

```text
请实现管理员后台的成员管理页面。功能包括成员列表、新增、编辑、停用和按分组筛选。请先读取现有代码结构，再按项目风格实现。完成后运行检查并总结。
```

### 6. Excel 导入成员

```text
请实现 Excel 导入成员功能。要求支持读取成员姓名、学号、性别、手机号和分组。请先说明使用的 Excel 解析库和数据校验方案，等我确认后再修改代码。
```

### 7. 签到任务创建

```text
请实现创建签到任务页面。功能包括填写标题、选择分组/成员、设置规定签到时间和结束时间，并生成 session_members 记录。请先说明数据写入流程，等我确认后再实现。
```

### 8. 签到详情和导出

```text
请实现签到详情页面和 Excel 导出功能。详情页需要展示成员签到状态、签到时间、迟到分钟数和缺勤情况。导出 Excel 需要包含完整考勤结果。完成后运行检查并总结。
```

### 9. Flutter App 项目初始化

```text
请在正式项目中初始化 Flutter 安卓 App。不要实现业务逻辑。请先说明目录规划和创建命令，等我确认后再执行。初始化后运行 flutter pub get 和安卓真机验证。
```

### 10. Flutter App 基础 UI

```text
请为 Flutter App 创建基础 UI，包括启动页、当前签到页、成员签到列表页、签到确认弹窗和签到结果提示。先使用静态假数据，不接入 Supabase。
```

### 11. Flutter App 接入 Supabase

```text
请为 Flutter App 接入 Supabase。请先说明需要的环境变量、依赖包和初始化方式，等我确认后再修改代码。不要把 Supabase key 写死在业务代码中。
```

### 12. 签到逻辑

```text
请实现 Flutter App 的点击成员签到逻辑。规则是当前时间 <= required_time 为 normal，required_time < 当前时间 <= end_time 为 late，并计算 late_minutes。完成后运行检查。
```

### 13. 缺勤逻辑

```text
请实现结束签到后的缺勤逻辑。要求将 end_time 后仍为 pending 的成员标记为 absent，并禁止继续签到。请先说明由后台触发还是数据库函数触发，等我确认后再实现。
```

### 14. 安卓真机测试

```text
请帮我进行安卓真机测试。只运行已有 Flutter App，不新增业务功能。请检查 flutter devices，运行到设备，记录是否构建、安装、启动成功，并保留错误日志。
```

### 15. 打包 APK

```text
请帮我打包 Flutter Android APK。请先检查版本号、应用名和构建配置。等我确认后执行 flutter build apk，并告诉我 APK 输出路径。
```

## 四、每个阶段完成后的确认项

每个阶段完成后，都需要确认以下内容：

- 修改了哪些文件
- 是否运行成功
- 是否有报错
- 是否执行了必要检查
- 是否有未完成事项
- 下一步是什么

如果出现错误，需要额外确认：

- 错误发生在哪个命令或功能
- 最后关键错误日志是什么
- 判断属于配置问题、代码问题、依赖问题还是网络问题
- 下一步建议如何修复
